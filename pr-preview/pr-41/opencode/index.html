OpenCode¶

OpenCode reads skills in the open Agent Skills format directly, and it has no plugin marketplace and no hooks.json. So a Lightcone plugin installs on OpenCode in two parts: the skills through the skills CLI, and the hooks as a single OpenCode plugin file that this repository generates from the same hook scripts Claude Code and Codex run.

Install¶

The only prerequisite is uv, as on every harness. The examples install astra; substitute lightcone for the full stack — its directory ships both skills and its plugin file includes astra's hooks, so do not install both.

1. Skills — with the skills CLI, pointed at the packaged plugin directory:

npx skills add https://github.com/LightconeResearch/agent-skills/tree/main/plugins/astra -a opencode -g

This installs into ~/.agents/skills/, one of the directories OpenCode scans. Drop -g to install into the current project (./.agents/skills/) instead.

2. Hooks — one JavaScript file, copied into OpenCode's plugin directory:

mkdir -p ~/.config/opencode/plugins
curl -fsSL https://raw.githubusercontent.com/LightconeResearch/agent-skills/main/plugins/astra/opencode/astra.js \
  -o ~/.config/opencode/plugins/astra.js

Use .opencode/plugins/ inside a project for a per-project install. Restart OpenCode; the plugin loads at startup.

What the plugin does¶

plugins/<name>/opencode/<name>.js is generated by npm run build from the plugin's hooks.json. It embeds the hook scripts verbatim — tool versions already pinned — and maps the hook events onto OpenCode's plugin API:

hooks.json event OpenCode hook Effect
PostToolUse (Write\|Edit\|apply_patch) tool.execute.after on write, edit, patch Whenever a save touches astra.yaml, the spec is re-validated and the report is appended to the tool result the model reads.
SessionStart experimental.chat.system.transform (pre-warmed on session.created) The session primer — spec location and analysis shape, and for lightcone the state of the lc engine — runs once per session and is added to the system prompt on every request.

Nothing else is installed. The file needs bash on PATH; the scripts need uvx and tell the agent when it is missing, exactly as on the other harnesses.

Experimental hook

The session primer relies on experimental.chat.system.transform, which OpenCode marks experimental. If a release renames it, validate-on-save keeps working and only the primer goes quiet — please open an issue.

Using the skills¶

OpenCode does not namespace skills by plugin: the agent loads astra or lightcone through its skill tool when the task matches the description, and you can simply ask it to "use the astra skill".

Differences from Claude Code and Codex¶

  • No marketplace. Updates are a re-run of the two install commands.
  • Interactive or not? The lightcone primer asks the user before installing or upgrading lc when a person may be present. OpenCode does not expose how it was launched, so the primer always asks — in a headless opencode run the agent will report instead of acting.
  • Uninstall by deleting ~/.agents/skills/<skill>/ and ~/.config/opencode/plugins/<plugin>.js.

Try it¶

The getting started tutorial works on OpenCode as it does elsewhere: the validate-on-save hook fires when the agent writes the spec.

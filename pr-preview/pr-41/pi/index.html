Pi¶

Pi reads skills in the open Agent Skills format and installs extension packages from npm, so a Lightcone plugin installs in one step — skills and hooks together — from the same npm package OpenCode uses.

Install¶

The only prerequisite is uv, as on every harness. The example installs astra; for the full stack substitute lightcone — its package ships both skills and includes astra's hooks, so do not install both.

pi install npm:@lightcone-research/astra-plugin@0.0.5

Pi installs the package under ~/.pi/agent/npm/ and picks up its skills/ directory and its extension. Pin the version: it is the plugin version shown in the README, and pi update leaves pinned packages alone. To try before installing: pi -e npm:@lightcone-research/astra-plugin.

What the package does¶

@lightcone-research/astra-plugin is plugins/astra/ published as-is: the packaged skills, plus pi/index.js, an extension generated by npm run build from the plugin's hooks.json. It embeds the hook scripts verbatim — tool versions already pinned — and maps the hook events onto Pi's extension API:

hooks.json event Pi event Effect
PostToolUse (Write\|Edit\|apply_patch) tool_result on write, edit Whenever a save touches astra.yaml, the spec is re-validated and the report is appended to the tool result as a text block.
SessionStart session_start + before_agent_start The session primer — spec location and analysis shape, and for lightcone the state of the lc engine — runs once per session and is appended to the system prompt on every turn.

The extension has no dependencies. It needs bash on PATH (Git Bash or WSL on Windows); the scripts need uvx and tell the agent when it is missing, exactly as on the other harnesses.

Using the skills¶

Pi lists installed skills in the system prompt and loads one on demand; you can also invoke one directly as /skill:astra or /skill:lightcone. Skills are not namespaced by plugin. Do not add the skills a second time with the skills CLI — Pi warns on duplicate names and keeps the first.

Updating and removing¶

  • Update: pi install npm:@lightcone-research/astra-plugin@<new version>.
  • Remove: pi remove npm:@lightcone-research/astra-plugin.

Differences from Claude Code and Codex¶

  • No marketplace, but a one-line install that covers skills and hooks.
  • Interactive or not? The lightcone primer asks the user before installing or upgrading lc when a person may be present. The extension does not yet tell the scripts whether Pi runs interactively, so the primer always asks — in pi -p (print mode) the agent will report instead of acting. A future release can pass Pi's own signal through.

Try it¶

The getting started tutorial works on Pi as it does elsewhere: the validate-on-save hook fires when the agent writes the spec.

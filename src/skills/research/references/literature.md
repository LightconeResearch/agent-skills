# When to look at the literature

Mechanics — caching papers, the subagent fan-out, writing insights — are
the lightcone skill's `references/literature.md`. This file is the judgment.

## When

Run a pass when the user asks for one, or propose one when a choice of
scientific substance is on the table — which method, which cut, which
model, what to hold fixed — and a reading of the literature would change how
it gets decided. Propose rather than launch: collecting candidates costs
little, so present them as the proposal; extract only after approval, and
don't re-propose for a choice the user has declined to research.

## Why the order is collect, then extract, then identify decisions

Decisions identified before the papers are read end up being the ones the
analyst already had in mind.

## What makes a paper relevant

It bears on a decision in the spec: it compares the options, justifies one
of them, or fixes a threshold or cut the analysis depends on.

## Identifying decisions from the literature

From the conversation *and* the papers: what could be done differently and
still be defensible? Where did papers disagree or compare alternatives?
Where was the user uncertain? Probe the blind spots analysts neglect — data
exclusion, variable operationalization, inference criteria — not just method
choices.

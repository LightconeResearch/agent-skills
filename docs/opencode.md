# OpenCode

[OpenCode](https://opencode.ai) reads skills in the open
[Agent Skills](https://agentskills.io) format directly, and it installs plugins
from npm: packages listed under `plugin` in `opencode.json` are installed
automatically at startup. So a Lightcone plugin arrives in two parts — the
**skills** through the `skills` CLI, and the **hooks** as an npm package that
this repository publishes from the very same hook scripts Claude Code and Codex
run.

## Install

The only prerequisite is
[`uv`](https://docs.astral.sh/uv/getting-started/installation/), as on every
harness. The examples install `astra`; for the full stack substitute
`lightcone` — its package includes `astra`'s hooks, so do not list both.

**1. Skills** — with the [`skills` CLI](https://github.com/vercel-labs/skills),
pointed at the packaged plugin directory:

```bash
npx skills add https://github.com/LightconeResearch/agent-skills/tree/main/plugins/astra -a opencode -g
```

This installs into `~/.agents/skills/`, one of the directories OpenCode scans.
Drop `-g` to install into the current project (`./.agents/skills/`) instead.

**2. Hooks** — add the package to `opencode.json`
(`~/.config/opencode/opencode.json` for every project, or a project's own):

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@lightcone-research/astra-plugin@0.0.5"]
}
```

OpenCode installs it on the next start. **Pin the version**: OpenCode resolves
an unpinned spec once and keeps that copy in its cache, so `@latest` would not
pick up new releases. The package version is the plugin version shown in the
[README](https://github.com/LightconeResearch/agent-skills#-plugins).

## What the plugin does

`@lightcone-research/astra-plugin` is `plugins/astra/` published as-is: the
packaged skills, plus `opencode/index.js`, a module generated by
`npm run build` from the plugin's `hooks.json`. It embeds the hook scripts
verbatim — tool versions already pinned — and maps the hook events onto
OpenCode's plugin API:

| `hooks.json` event | OpenCode hook | Effect |
|---|---|---|
| `PostToolUse` (`Write\|Edit\|apply_patch`) | `tool.execute.after` on `write`, `edit`, `apply_patch` | Whenever a save touches `astra.yaml`, the spec is re-validated and the report is appended to the tool result the model reads. |
| `SessionStart` | `experimental.chat.system.transform` (pre-warmed on `session.created`) | The session primer — spec location and analysis shape, and for `lightcone` the state of the `lc` engine — runs once per session and is added to the system prompt on every request. |

The module has no dependencies. It needs `bash` on PATH (Git Bash or WSL on
Windows); the scripts need `uvx` and tell the agent when it is missing, exactly
as on the other harnesses.

!!! note "Experimental hook"

    The session primer relies on `experimental.chat.system.transform`, which
    OpenCode marks experimental. If a release renames it, validate-on-save
    keeps working and only the primer goes quiet — please open an issue.

## Using the skills

OpenCode does not namespace skills by plugin: the agent loads `astra` or
`lightcone` through its `skill` tool when the task matches the description,
and you can simply ask it to "use the astra skill".

## Updating and removing

- **Update**: bump the pinned version in `opencode.json` and re-run the
  `npx skills add …` line for the skills.
- **Remove**: delete the `plugin` entry and `~/.agents/skills/<skill>/`.

## Differences from Claude Code and Codex

- **No marketplace.** Two install lines instead of one, no in-app catalogue.
- **Interactive or not?** The `lightcone` primer asks the user before
  installing or upgrading `lc` when a person may be present. OpenCode does not
  expose how it was launched, so the primer always asks — in a headless
  `opencode run` the agent will report instead of acting.

## Try it

The [getting started tutorial](getting-started.md) works on OpenCode as it
does elsewhere: the validate-on-save hook fires when the agent writes the spec.
